Лекция 1: Въведение в MVC и настройка на проекта

Цели на обучението

  • Разбиране на архитектурата MVC и нейните компоненти: Model, View, Controller.
  • Настройка на средата за разработка.
  • Създаване на нов ASP.NET MVC проект.

Съдържание

  1. Какво е HTTP?
    • Защо ни е нужен HTTP? Клиент–сървър модел.
    • Структура на HTTP заявка (метод, URL, хедъри, тяло).
    • HTTP методи: GET, POST, PUT, DELETE.
    • Структура на HTTP отговор.
    • Често срещани статус кодове: 200, 301, 302, 400, 401, 403, 404, 500.
  2. Какво е .NET, ASP.NET, C#
    • Какво е framework и защо ни улеснява.
    • .NET SDK, runtime, CLI (dotnet new, dotnet run).
  3. Основи на C# (преговор, ускорено темпо)
    • Защо C# за уеб разработка.
    • Структура на C# програма; типове данни и променливи.
    • Управляващи конструкции (if, switch, цикли).
    • Колекции: масиви, List<T>, Dictionary<K,V>.
    • Методи и параметри; класове и обекти; свойства.
    • Работа с изключения (try / catch / finally).
    • LINQ – само базовите оператори Where, Select, OrderBy, FirstOrDefault.
  4. Какво е MVC?
    • Преглед на Model, View и Controller и ролята на всеки компонент.
    • Разделяне на отговорностите; предимства на архитектурата.
    • Жизнен цикъл на една заявка в ASP.NET Core MVC.
  5. Инсталиране и настройка на инструментите
    • Изтегляне на .NET SDK.
    • Visual Studio Community Edition или алтернатива според ОС.
    • Настройка на SQL Server Express / LocalDB и SQL Server Management Studio.
  6. Създаване на първия ASP.NET MVC проект
    • Стъпка по стъпка създаване на проект (шаблон ASP.NET Core Web App (MVC)).
    • Структура на папките: Models, Views, Controllers, wwwroot.
    • Роля на Program.cs и appsettings.json.
  7. Практически пример: стартиране на уебсайта за библиотеката
    • Създаване на проект с име LocalLibrary.
    • Стартиране и разглеждане на генерираната страница в браузъра.
    • Обсъждане на автоматично генерираните файлове.

Практическа задача

  • Създайте нов ASP.NET MVC проект и го стартирайте в браузъра.
  • Разгледайте структурата на папките и идентифицирайте ключовите файлове.

 

Лекция 2: Контролери и маршрутизиране

Цели на обучението

  • Как работят контролерите в MVC.
  • Как маршрутизирането свързва URL адреси с контролери и действия.

Съдържание

  1. Какво е контролер?
    • Роля на контролерите при обработката на HTTP заявки.
    • Създаване на персонализиран контролер в папка Controllers.
    • Конвенции за именуване (XxxController).
  2. Добавяне на действия (actions)
    • Дефиниране на действия и връщане на изглед (IActionResult, View()).
    • Приемане на параметри от URL и от заявка.
    • Пример: LibraryController с действие Index.
  3. Маршрутизиране (Routing)
    • Как маршрутът свързва URL с метод за действие.
    • Конвенционално маршрутизиране ({controller}/{action}/{id?}).
    • Атрибутно маршрутизиране ([Route], [HttpGet]).
  4. Практически пример: основни страници
    • LibraryController с действия за начална страница (Index), „За нас“ (About) и „Контакт“ (Contact).

Практическа задача

  • Създайте LibraryController и дефинирайте основните методи за действие.
  • Добавете персонализирани маршрути, така че страниците да се отварят на конкретни URL адреси.

 

Лекция 3: Изгледи и стилизиране с Bootstrap

Цели на обучението

  • Създаване и персонализиране на изгледи в MVC.
  • Използване на Bootstrap за основно стилизиране.

Съдържание

  1. Какво е изглед?
    • Роля на изгледите при представянето на данните.
    • .cshtml файлове: C# + HTML + CSS.
    • Роля на HTML и CSS; основни HTML елементи и структура на документа; CSS основи (селектори, кутиен модел).
    • Razor синтаксис за динамично рендиране (@, @if, @foreach, @model).
    • Глобални изгледи (_Layout), частични изгледи (partial views) и секции (sections).
  2. Създаване и персонализиране на изгледи
    • Изглед за метод на действие в контролера.
    • Предаване на данни от контролера към изгледа: ViewData, ViewBag и ViewModel (препоръчителен подход).
  3. Стилизиране с Bootstrap
    • Включване на Bootstrap в проекта.
    • Grid система, компоненти (navbar, card, table, form), отзивчив дизайн.
  4. Практически пример: начална страница
    • Изглед за действието Index в LibraryController.
    • Навигационно меню, долен колонтитул и основно съдържание с Bootstrap.

Практическа задача

  • Създайте начална страница със заглавие, навигационни връзки и приветствие.
  • Използвайте Bootstrap за подобряване на визията на страницата.

 

Лекция 4: Интегриране на база данни с Entity Framework Core

Цели на обучението

  • Роля на модела в MVC.
  • Използване на Entity Framework за свързване с база данни.

Съдържание

  1. Какво е модел?
    • Роля на моделите за представяне на данните.
    • Въведение в ORM и Entity Framework Core.
  2. Настройка на базата данни
    • Създаване на SQL Server база данни за библиотеката.
    • Connection string в appsettings.json.
    • Модел Book с полета Title, Author, PublishedDate, ISBN.
  3. Code-First подход
    • DbContext и DbSet<T>; регистрация чрез Dependency Injection.
    • Атрибути за данни: [Key], [Required], [MaxLength], [DataType].
    • Миграции: Add-Migration / Update-Database (Package Manager Console) или dotnet ef migrations add / dotnet ef database update.
    • Начално зареждане на данни (seeding).
  4. Релации между таблиците
    • Видове релации: 1:1, 1:M (един към много) и M:M (много към много).
    • Външни ключове и навигационни свойства; конфигуриране чрез Data Annotations и Fluent API.
    • 1:M пример: Author → много Book; Category → много Book.
    • M:M пример: Book ↔ Author или Book ↔ Tag; свързваща таблица и как EF Core я създава автоматично.
    • Зареждане на свързани данни: Include (eager loading) и защо липсата му води до празни навигационни свойства.
    • Каскадно изтриване и ограничения за цялост.
  5. Практически пример: списък с книги
    • BookController, инжектиране на DbContext.
    • Извличане на списък с книги заедно с автора и категорията им (Include) и показването му в изглед (таблица с Bootstrap).

Практическа задача

  • Създайте моделите Book, Author и Category с релации 1:M и M:M и генерирайте базата данни чрез миграция.
  • Покажете списък с книги, в който се вижда информация и от свързаните таблици.

 

Лекция 5: CRUD операции и завършване на уебсайта

Цели на обучението

  • Реализиране на CRUD операции за управление на данни.
  • Отстраняване на грешки и подготовка за разгръщане.

Съдържание

  1. Какво са CRUD операции?
    • Създаване, четене, редактиране и изтриване на записи.
    • Реализация в контролер: GET/POST двойки действия.
  2. Форми за въвеждане на данни
    • Razor форми и Tag Helpers: asp-for, asp-action, asp-validation-for.
    • Валидация от страна на модела (Data Annotations) и в изгледа (ModelState.IsValid, validation summary).
    • Защита срещу CSRF: [ValidateAntiForgeryToken].
  3. CRUD в BookController
    • Добавяне на нова книга; преглед на детайли; редактиране; изтриване с потвърждение.
    • Работа със свързани данни във формите: падащо меню за 1:M връзка (SelectList) и множествен избор за M:M връзка.
    • Използване на scaffolding за автоматично генериране и последващо ръчно доработване.
  4. Откриване и отстраняване на грешки
    • Debugger във Visual Studio: breakpoints, watch, call stack.
    • Developer Exception Page, страници за грешки, логване.
  5. Разгръщане (deployment)
    • Публикуване към IIS / Azure App Service; publish профил.
    • Прилагане на миграции към продукционна база.
  6. Практически пример: завършване на уебсайта за библиотеката
    • Пълна функционалност за управление на каталога и тестване на приложението.

Практическа задача

  • Реализирайте CRUD операции за модела Book.
  • Тествайте приложението — добавяне, редактиране и изтриване на книги.

 

Лекция 6: Автентикация и оторизация

Цели на обучението

  • Да се разбира разликата между автентикация (кой си) и оторизация (какво ти е позволено).
  • Реализиране на регистрация, вход и роли в ASP.NET Core.

Съдържание

  1. Автентикация срещу оторизация
    • Кой е потребителят срещу какво има право да прави.
    • Как HTTP запазва „кой си“ между заявките: cookies, сесии, токени.
  2. ASP.NET Core Identity
    • Добавяне на Identity към съществуващ проект; таблиците, които създава.
    • Регистрация и вход; хеширане на паролите; изисквания към паролата.
    • SignInManager, UserManager; изход (logout).
    • Cookie автентикация за MVC частта.
  3. Оторизация
    • Атрибут [Authorize] и [AllowAnonymous].
    • Роли (например Administrator, Librarian, Member) и [Authorize(Roles = "...")].
    • Скриване на елементи в изгледа според ролята (User.IsInRole, SignInManager.IsSignedIn).
    • Свързване на записите с потребителя, който ги е създал.
  4. Токен-базирана автентикация (JWT)
    • Защо cookie не е удобно за SPA и мобилни клиенти.
    • Структура на JWT; издаване на токен при вход; валидиране; срок на живот.
    • Подготовка за Лекция 7 — API-то ще се защитава с JWT.
  5. Основи на сигурността
    • Съхранение на тайни: user secrets и environment variables вместо appsettings.json.
    • Кратък преглед: SQL Injection, XSS, CSRF и как рамката помага срещу тях.
  6. Практически пример
    • Регистрация и вход в приложението.
    • Само администратор може да добавя, редактира и изтрива книги; останалите потребители само разглеждат каталога.

Практическа задача

  • Добавете регистрация и вход към проекта си.
  • Дефинирайте поне две роли и защитете CRUD действията само за едната от тях.

 

Лекция 7: REST API и SPA клиент с Vue 3

Цели на обучението

  • Да се изгради REST API върху вече съществуващите модели и база данни.
  • Да се създаде отделен фронтенд на Vue 3, който консумира този API.

Съдържание

  1. Защо API?
    • Server-rendered (Razor) срещу SPA — сравнение и кога кое е подходящо.
    • Един бекенд, много клиенти: уеб, мобилно приложение, външна интеграция.
  2. REST принципи
    • Ресурси и URI дизайн (/api/books, /api/books/{id}).
    • Правилна употреба на HTTP методите и статус кодовете.
    • Странициране, търсене и филтриране чрез query параметри.
  3. Реализация на API в ASP.NET Core
    • [ApiController], ActionResult<T>, връщане на Ok, Created, NotFound, BadRequest.
    • DTO класове — защо не връщаме ентитетите от базата директно.
    • Валидация на входа и връщане на смислени грешки.
    • Документация със Swagger / OpenAPI и тестване през Swagger UI.
    • CORS — разрешаване на достъп от адреса на Vue приложението.
    • Защита на endpoint-ите с JWT от Лекция 6.
  4. Основи на Vue 3
    • Създаване на проект с Vite; структура на папките.
    • Single-File Components (.vue): template, script, style.
    • Composition API: ref, computed, onMounted.
    • Шаблонен синтаксис: v-if, v-for, v-model, v-bind, v-on.
    • Компоненти, props и събития.
  5. Свързване на Vue с .NET API
    • HTTP заявки с fetch или axios; базов URL и dev прокси във Vite.
    • Показване на списък от API-то; състояния „зареждане“, „грешка“, „няма данни“.
    • Форма за добавяне и редактиране; изпращане на POST / PUT / DELETE.
    • Навигация с vue-router; защитен маршрут според това дали потребителят е влязъл.
    • Вход от Vue: получаване на JWT, съхранение и прикачване на Authorization хедър.
  6. Практически пример
    • BooksController (API) с пълен CRUD.
    • Vue приложение с каталог на книгите, детайлна страница, форма за редакция и страница за вход.

Практическа задача

  • Изградете REST API за поне един обект с пълен CRUD и Swagger документация.
  • Създайте Vue 3 приложение с поне 3 маршрута, което консумира този API и има поне един защитен маршрут.

 

Финален проект

Задача: Завършено уеб приложение

Тема: Свободна

  • Копие на съществуващо приложение (Reddit, X, Facebook и др.).
  • Или уеб приложение за библиотека, училище, събития, спортен клуб, музей, университет.

Екип: Проектът може да се разработва индивидуално или в екип до трима участници, като при работа в екип изискванията се повишават съгласно методиката по-долу. Задължително условие за екипните проекти е използването на Git репозитори, в което ясно да се вижда приносът на всеки член. Темата и съставът на екипа се изпращат предварително на лектора. Ако участник се откаже, зададените изисквания за екипа не се занижават.

Минимални изисквания

1. Структура и функционалност

  • Начална страница.
  • Страница с информация за проекта (екип, основни функции, използвани технологии).
  • Изградена MVC архитектура (Model–View–Controller).
  • Навигационно меню с достъп до основните секции.
  • Поне N* страници с динамично съдържание (например списък с книги, информация за събития, профили).
  • .NET версия 8 или по-нова.

2. Работа с база данни

  • Интеграция със SQL база данни чрез Entity Framework.
  • Пълна CRUD функционалност за поне E* обекта (например книги, автори, членове).
  • Задължително реализирани поне една връзка „един към много“ (1:M) и поне една връзка „много към много“ (M:M), използвани смислено в приложението (например филтриране или показване на свързаните данни).
  • Реализирани валидации на данните (и в модела, и в изгледите).
  • Обработени изключения и грешки (например при грешен вход или липсващи данни).

3. Потребителски интерфейс

  • Използвана стилизираща библиотека — Bootstrap или TailwindCSS.
  • Използване на Razor изгледи за визуализация.
  • Ясно оформление и лесна навигация.
  • Използване на поне L* от следните 3 техники: Layout, Partial View, Section.

4. Автентикация, API и SPA (задължително за тази дисциплина)

  • Регистрация и вход на потребители.
  • Поне две роли с различни права; защитени действия за редакция и изтриване.
  • REST API с DTO-та, валидация, коректни статус кодове и Swagger документация за поне A* обекта.
  • SPA клиент на Vue 3 (или друг съгласуван JS framework) с поне S* маршрута, който консумира API-то и има поне един защитен маршрут.

5. Допълнителни точки (по желание)

  • Връзка „едно към едно“ (1:1) или по-сложен модел на данните.
  • Търсене / филтриране на данни.
  • Автоматизирани тестове.
  • Разгърнато приложение на публичен адрес.
