Block 2 · 30 min

Passing data to a view

Three mechanisms, in increasing order of discipline.

Microsoft Web Technologies

Passing data to a view · the idea

What does one page actually need?

  • The articles themselves.
  • A page heading.
  • How many results there are.
  • The author currently filtered on — or "all".
  • The list of authors to offer as filters.
  • Whether the visitor may write a new article.

Six things, five different types

A list of articles carries exactly one of them.

So the real question is not "how do I send a list?" but: what is the shape of the box we hand from the handler to the template?

Microsoft Web Technologies

Passing data to a view · the idea

Every framework offers the same three answers

MechanismWhat it looks likeChecked before it runs?
An untyped bag of key/value pairsbag["title"] = "Articles"no — any key is accepted
A dynamic objectbag.Title = "Articles"no — any property is accepted
A purpose-built class for this pagenew ArticleListPage { … }yes — the compiler checks it
The third is the professional default. The first two are convenient, and convenience is exactly what makes them dangerous.
Microsoft Web Technologies

The whole argument, in one sentence

A typo in the first two is discovered by a user.
A typo in the third is discovered by the compiler.

One of those costs a keystroke. The other costs a bug report, a reproduction, and an afternoon.

Microsoft Web Technologies

Passing data to a view · in .NET

ViewData and ViewBag

// ArticlesController.cs
public IActionResult Index()
{
    ViewData["Title"] = "All articles";
    ViewBag.ArticleCount = _articles.Count;
    return View(_articles);
}
@* Index.cshtml *@
<h1>@ViewData["Title"]</h1>
<p>@ViewBag.ArticleCount article(s)</p>

String key, object value

ViewData is a dictionary. Everything comes back out as object, so casting is on us: ((List<string>)ViewData["Authors"]).

Dynamic property

ViewBag is dynamic. The property name is not resolved until the page renders.

The same store

They are two syntaxes over one dictionary. We set with one and read with the other, live, to prove it.

Microsoft Web Technologies

Demo · the keystroke that costs an afternoon

One wrong letter, and the page renders happily

@* what we meant *@
<p>@ViewBag.ArticleCount article(s)</p>
→ 12 article(s)

@* what we typed *@
<p>@ViewBag.ArticleCont article(s)</p>
→ article(s)
No error. No warning. No red squiggle. The number is simply missing, and only a person looking at the page will notice.

It compiles

A dynamic property name is not checked at build time. Anything you type is a legal expression.

It renders

An unknown key returns null, and null renders as nothing at all.

It ships

Unless a test or a human catches it. That is the entire case for a typed view model, in one keystroke.

Microsoft Web Technologies

Passing data to a view · in .NET

So when is ViewData still the right answer?

Keep

Small, cross-cutting values every page has

The page title is the canonical example. _Layout.cshtml reads ViewData["Title"], and every view sets it. That is why the project template ships it that way.

One shared slot, one shared reader, no per-page class.

Replace

Everything else

Anything a specific page needs — the list, the count, the filter, the authors — belongs on a view model.

The rule we apply for the rest of the course: exactly one use of ViewData per project, and it is the page title.

Block 3 · 25 min

View models: designing for the page

One class, one screen, nothing spare.

Microsoft Web Technologies

View models · the idea

Analogy: the tray

  • The kitchen does not send the fridge to the table.
  • It does not send the recipe book, or the supplier's invoice.
  • It plates exactly what was ordered, on one tray.
  • The tray exists for one table, for one order, and then it is gone.

A view model is that tray

A small object that exists for exactly one screen.

It is not the storage shape and not the business shape. It is "everything this page needs, and nothing else."

Microsoft Web Technologies

View models · the idea

Several sources in, one flat object out

Nothing on the right is a copy of a storage table. Every field on the right is there because the screen shows it.

Microsoft Web Technologies

View models · the idea

Why it is worth an extra file

It is a contract

The template declares what it needs; the handler must supply it. Neither side can drift without the other noticing.

It shows only what should be shown

A user record holds a password hash. A profile-page view model simply does not have that field, so it cannot leak — Session 09.

It can combine sources

Articles from one place, author names from another, the current filter from the address. One object.

It can pre-compute

Formatting and derived values are worked out before the template runs, instead of being tangled into the markup.

The cost is honest: one more small class per page. We accept it.
Microsoft Web Technologies

View models · in .NET

Models/ViewModels/ArticleListViewModel.cs

namespace SimpleBlog.Models.ViewModels;

public class ArticleListViewModel
{
    public IReadOnlyList<Article> Articles { get; set; }
        = new List<Article>();
    public string Heading { get; set; } = "Articles";
    public string? FilterAuthor { get; set; }
    public IReadOnlyList<string> AllAuthors { get; set; }
        = new List<string>();

    public int Count => Articles.Count;      // computed
    public bool IsFiltered => FilterAuthor is not null;
}

Plain properties

No base class, no attribute, no registration. A view model is an ordinary class.

Computed, not stored

Count and IsFiltered are derived on read. Nobody can set them to something inconsistent.

View models · in .NET

The controller fills the tray

public IActionResult Index(string? author)
{
    var list = string.IsNullOrWhiteSpace(author) ? _articles
        : _articles.Where(a => a.Author == author).ToList();
    return View(new ArticleListViewModel
    {
        Articles = list.OrderByDescending(a => a.PublishedOn).ToList(),
        Heading = author is null ? "All articles"
                                 : $"Articles by {author}",
        FilterAuthor = author,
        AllAuthors = _allAuthors
    });
}

The LINQ from Session 02 and the model binding from Session 03, combined: /articles?author=Ada now filters the page.

View models · in .NET

The view declares what it expects

@model SimpleBlog.Models.ViewModels
              .ArticleListViewModel

<h1>@Model.Heading</h1>
<p class="text-muted">@Model.Count article(s)</p>

The same typo, now

@Model.Cont is a compile error. The page will not build, let alone ship.

No logic beyond display

The view asks questions and prints answers. Deciding what to show happened in the controller.

Naming convention

<Page><Purpose>ViewModel, in Models/ViewModels/ — kept out of Models/ proper. The distinction matters from Session 07 on.

Block 5 · 25 min

CSS frameworks and responsive design

One page that adapts, rather than two sites that diverge.

Microsoft Web Technologies

CSS frameworks · the idea

How much CSS does a real site actually need?

Navigation that collapses on a phone. Buttons in five states. Forms, tables, dialogs. Spacing that is consistent across forty pages. All of it working in every browser.

Thousands of lines

And none of them are your blog. Every site rewrites the same stylesheet before it writes anything of its own.

So somebody wrote it once

A CSS framework is a pre-written stylesheet of ready-made classes and components. Bootstrap, Tailwind, Bulma, Foundation.

The same argument as Session 02

We did not write our own web server. We do not write our own button either. A framework is other people's solved problems.

How they work: we stop writing rules and start applying ready-made classes to our markup. Each class does one small, named thing — a padding, a margin, a border, a rounded corner.
Microsoft Web Technologies

CSS frameworks · the idea

Name the trade-off out loud

The cost

Markup gets noisier

Six or eight class names on an element is normal. Design decisions move out of the stylesheet and into the page, where they are harder to change in one place.

The cost

Somebody else's opinions

You inherit a spacing scale, a colour palette and a look that many other sites also have.

The gain

Consistent, responsive, fast

Forty pages that agree with each other, adapt to any screen, and were built in an afternoon rather than a fortnight.

The gain

A newcomer can read it

The names are documented and the same everywhere. For a course project — and for most business applications — that trade is clearly worth it.

Microsoft Web Technologies

Responsive design · the idea

One page that adapts, not two sites that diverge

The same page will be read on a 360 px phone and a 2560 px monitor. A layout built from fixed pixel widths is broken on one of them. Three mechanisms make one layout serve both:

1

Fluid widths

Percentages and fractions instead of fixed pixels. A block asks for "half the space", not "480 pixels".

2

The viewport meta tag

From Session 05. Without it a phone pretends to be 980 px wide and shrinks the whole page to fit. We delete it live and watch that happen.

width=device-width, initial-scale=1

3

Media queries

Rules that only apply above (or below) a given width. The layout changes shape at chosen points.

Microsoft Web Technologies

Responsive design · the idea

Mobile-first is a direction, not a slogan

/* the base: what every screen gets */
.sidebar { display: none; }

/* added from 768px upward */
@media (min-width: 768px) {
    .sidebar { display: block; width: 30%; }
}
Write the small-screen rules as the base, then add rules for wider screens.

It is easier to add than to undo

Starting wide means every narrow rule is a correction of a rule above it. Starting narrow means every wide rule is an addition.

The constrained device gets the simplest stylesheet

The phone — least screen, least power, worst connection — downloads and applies the fewest rules.

Read it as a minimum

min-width: 768px means "from 768 upward", not "at 768 only". Every wider screen gets it too.

Microsoft Web Technologies

Responsive design · the idea

Almost every framework divides the page into twelve

Twelve, because it divides by 2, 3, 4 and 6 — halves, thirds and quarters all land on a column edge. We say how many columns a block occupies, at each screen size.

Microsoft Web Technologies

Responsive design · the idea

The same three blocks, three widths

Nothing was hidden and nothing was duplicated. The same three blocks changed how many columns they occupy at two chosen widths — those widths are the breakpoints.

Microsoft Web Technologies

Responsive design · the idea

These slides are the same idea, running

This deck is not a picture of a design system. It is built on one, and it is worth looking at for a minute because every idea in this block is visible in it.

Named values, not literals

No colour, space, radius or shadow on these slides is typed as a number. Each one is a named token, defined once. Change the definition and every slide changes.

A grid, not guesswork

This row is three equal columns; the slide before it was two. The card boxes do not know their own width — they take whatever share the grid gives them.

Components, reused

Every box on this slide is the same card component. The small blue pills are the same badge component. Written once, used on forty slides.

And it is fluid: the whole deck is one fixed stage scaled to whatever window it is shown in — which is why it looks identical on a laptop and on the projector.

Block 6 · 25 min

The Bootstrap grid

Container, row, column — and five breakpoints.

Microsoft Web Technologies

Bootstrap · in the project

It is already there

dotnet new mvc ships Bootstrap 5 in wwwroot/lib/bootstrap/, referenced from _Layout.cshtml. We open both files and look.

<!-- in <head> -->
<link rel="stylesheet"
      href="~/lib/bootstrap/dist/css/bootstrap.min.css" />

<!-- last thing before </body> -->
<script src="~/lib/bootstrap/dist/js/bootstrap.bundle.min.js">
</script>

Why the script is at the bottom

The page renders before the JavaScript is fetched. A script in the <head> blocks the first paint.

CSS alone is not enough

The collapsing navbar, dropdowns and dialogs need that bundle. Copying a snippet without it is the most common "it doesn't work".

A CDN is the alternative: fewer files to host, but one more external dependency and no offline development. Local files are the safer default for a course.
Microsoft Web Technologies

Bootstrap · the grid

Three levels, always in this order

<div class="container">
  <!-- centred, max width, page padding -->
  <div class="row">
    <!-- a horizontal group of columns -->
    <div class="col-12 col-md-8">Main</div>
    <div class="col-12 col-md-4">Sidebar</div>
  </div>
</div>
A column outside a row is a bug. The row supplies the negative margins the columns' padding assumes — put a col-* straight in a container and the layout quietly breaks.

Read the class list aloud

col-12 col-md-8 is an English sentence:

"Full width by default; from medium screens upward, eight of twelve."

8 + 4 = 12

The two columns in the snippet are the fourth row of the grid diagram. They fill the row exactly. Go over twelve and the surplus wraps to the next line.

Microsoft Web Technologies

Bootstrap · the grid

Five breakpoints, all of them minimums

PrefixApplies fromTypical device
(none)0 pxphone
sm576 pxlarge phone
md768 pxtablet
lg992 pxlaptop
xl1200 pxdesktop

"From", never "at"

col-md-8 applies at 768 px and every width above it — unless a larger prefix overrides it. Mobile-first, exactly as in the previous block.

Demo

We resize the window and open the device toolbar. Watching the sidebar drop below the content at 768 px is the moment responsive design stops being abstract.

Spacing utilities, enough to be useful: m/p + side (t b s e x y) + step (0–5) — mb-3, p-4, px-2. Plus text-center, text-muted, d-flex, justify-content-between, align-items-center.
Microsoft Web Technologies

Bootstrap · the grid

What a utility class replaces

<!-- what we would have written -->
<div style="padding:1rem; margin-bottom:1rem;
            border:1px solid #dee2e6; border-radius:.375rem">

<!-- what we write instead -->
<div class="p-3 mb-3 border rounded">

Four names, four decisions, and the same four decisions on every other page of the site.
This is the trade we named in Part 1, in six lines.

Walkthrough · 25 min · from the front

We build the SimpleBlog home page

  1. We create ArticleListViewModel with Articles, Heading, FilterAuthor, AllAuthors and a computed Count.
  2. We rewrite ArticlesController.Index(string? author) to build it and pass it, newest first.
  3. We rewrite Views/Articles/Index.cshtml to take @model ArticleListViewModel.

Wrap-up

Common misconceptions — passing data

MisconceptionCorrection
"ViewData and ViewBag are different stores."Two syntaxes over the same dictionary. Set with one, read with the other.
"ViewBag is simpler, so it is better."It is unchecked. A typo fails silently at runtime and renders nothing.
"The view model must match the database table."It matches the page. It may combine sources, omit fields, or compute new ones.
"A view model is extra work for nothing."It is the difference between a compile error and a user-visible bug.
Microsoft Web Technologies

Wrap-up

Common misconceptions — layout

MisconceptionCorrection
"Bootstrap makes the site responsive automatically."Only if you use the grid classes and keep the viewport meta tag.
"col-md-8 means eight columns on medium screens only."It means "from medium upward". Breakpoints are minimum widths.
"You can put columns directly in a container."Columns must live inside a row.
"Using Bootstrap means never writing CSS."You still write your own for anything specific to your site.
"Copy any Bootstrap snippet and it works."Interactive components need bootstrap.bundle.min.js as well as the stylesheet.

Check for understanding

Six questions

  1. ViewBag.Titel = "x" in the controller, @ViewBag.Title in the view. What does the user see, and when do we find out?
  2. A page shows articles and a list of categories with counts. Which mechanism, and what would the class look like?
  3. Read class="col-12 col-md-6 col-lg-3" aloud as an English sentence.
  1. What happens to a Bootstrap page on a phone if the viewport meta tag is missing?
  2. Why is bootstrap.bundle.min.js at the bottom of the <body> and not in the <head>?
  3. Name one thing a view model can do that passing the domain object directly cannot.

Before we move on

Where SimpleBlog is

A styled, responsive site

Bootstrap navbar and footer in the layout, the article list as a responsive card grid driven by ArticleListViewModel, author filtering through the query string, and a styled details page.

The data is still the in-memory list.

If we have time

Two extensions

· An ArticleDetailsViewModel carrying the article plus its previous and next neighbours, with buttons that disappear when there is nothing to link to.

· A featured-article hero at col-12, put on the view model rather than fetched twice.

Worth breaking on purpose

Two failures to have seen

· A col-* placed directly in a container, with no row.

· The viewport meta tag deleted, viewed at 375 px.

Both fail quietly. Recognising them later is worth two minutes now.
