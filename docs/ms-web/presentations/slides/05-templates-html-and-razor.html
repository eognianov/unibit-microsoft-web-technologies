Block 2 · 30 min

HTML: the structure of a document

Labelling the parts of a page so that a browser knows what they are.

Microsoft Web Technologies

HTML

Analogy: the newspaper page

  • A newspaper page has a masthead, a headline, a byline, body paragraphs, a photo with a caption, a sidebar.
  • HTML gives each of those parts a name. That is all it does.
  • The label is the HTML. The look is CSS — the next block.
  • The reader of those labels is the browser, and also a screen reader and a search engine.

HTML is not a programming language

It has no decisions, no loops, no variables and no arithmetic. It is a markup language: it marks up a document, and nothing more.

Anything that decides or repeats happens elsewhere. That is the whole second half of this session.

Microsoft Web Technologies

HTML

One element, four parts

<p class="lead">Hello</p>
└┬┘└────┬─────┘ └─┬─┘└─┬┘
 │      │         │    └── closing tag — same name, with a slash
 │      │         └── content — what the reader sees
 │      └── attribute — name="value", extra information
 └── opening tag — what this thing is
A few elements have no content and no closing tag — <br>, <hr>, <img>, <meta>. They are written on their own.
Attributes always live in the opening tag, never in the closing one.
Microsoft Web Technologies

HTML

The smallest document that is worth writing

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="utf-8" />
    <meta name="viewport"
          content="width=device-width, initial-scale=1" />
    <title>SimpleBlog</title>
</head>
<body>
    <h1>Latest articles</h1>
</body>
</html>

<head>

Information about the page. Nothing here is displayed.

<body>

Everything the reader sees.

<title>

The browser tab, and the heading in a search result.

charset="utf-8" — without it, Cyrillic text arrives as mojibake. We delete the line and watch it happen.
viewport — required for the page to behave on a phone. We come back to it in Session 06.

Microsoft Web Technologies

HTML

Two rules that prevent most beginner pain

Rule 1

Nesting must be balanced

<p><strong>x</strong></p>

<p><strong>x</p></strong>

Elements open and close like brackets. The one opened last is closed first. A browser will guess when you get this wrong, and it will guess differently from the next browser.

Rule 2

Prefer a semantic element to a <div>

<nav> … </nav>

<div class="nav"> … </div>

<nav> says "navigation" to a screen reader and to a search engine. <div class="nav"> says nothing to anyone but you.

Microsoft Web Technologies

Live · HTML

Ten lines and a browser

<body>
  <header><h1>SimpleBlog</h1></header>
  <main>
    <article>
      <h2>Hello, world</h2>
      <p class="meta">by Ana · 5 May</p>
      <p>The <strong>first</strong> article.</p>
      <p><a href="/articles/1">Read more</a></p>
    </article>
  </main>
  <footer>© 2026 SimpleBlog</footer>
</body>
  1. We save this as a plain .html file and open it directly in the browser. No server, no framework, no project.
  2. We open DevTools and select Elements: the same document, drawn as a tree.
  3. We expand and collapse a branch. Nesting on screen is nesting in the file.
Not one line of this is styled, and it already reads correctly: a heading is a heading, a paragraph is a paragraph. Structure first, looks second.

Block 3 · 25 min

CSS: selectors and the box model

Given elements labelled like that — how should they look?

Microsoft Web Technologies

CSS

A rule, dissected

h1 { color: darkslateblue; font-size: 2rem; }
└┬┘  └─────────────────┬──────────────────┘
 │                     └── declarations — property: value;
 │                         one per pair, semicolon-separated
 └── selector — which elements this applies to

Selector

Answers which elements. Everything before the brace.

Property

Answers what about them — colour, size, spacing, position.

Value

Answers how much. Units matter: px, rem, %.

Microsoft Web Technologies

CSS

Four selectors cover almost everything

h1            { }   /* every <h1>           by element  */
.lead         { }   /* class="lead"         by class    */
#main-title   { }   /* id="main-title"      by id       */
article p     { }   /* <p> inside <article> descendant */

Style by class

A class can be reused on any number of elements, and one element can carry several. This is the workhorse.

Ids sparingly

An id must be unique on the page. Useful for linking to a position; rarely the right tool for styling.

An element selector sets a default for the whole site — every <h1>, every <p>. Reach for a class the moment you want some of them to differ.
Microsoft Web Technologies

CSS

Every element is a box, and every box has four bands

Microsoft Web Technologies

CSS

"How wide is a box that says width: 300px?"

The default

344 pixels

width means the width of the content band only. Padding and border are added on top of it. The number you wrote is not the number on screen.

With border-box

300 pixels

width means the width of the box including padding and border. The content band shrinks to fit. The number you wrote is the number on screen.

*, *::before, *::after { box-sizing: border-box; }
Three lines from the top of every real stylesheet, Bootstrap's included — Session 06. We write it once and stop doing arithmetic.
Microsoft Web Technologies

CSS

Three ways to attach a stylesheet — use the third

<p style="color:red">inline</p>      /* avoid: one element */

<style> p { color: red; } </style>   /* in <head>: one page */

<link rel="stylesheet" href="/css/site.css" />
                                     /* external: do this  */

One file, every page

The look of the whole site lives in one place, and one edit changes every page at once.

It is a second request

Session 01: that <link> makes the browser send another HTTP request. We watch it appear in the Network tab.

Which is why it is cached

The browser keeps the file and reuses it on the next page. An inline style is re-sent every time.

One HTML document, one stylesheet, two images and one script is not one request. It is five.

Block 5 · 15 min

Templates and server-side rendering

We have data in a list and the browser needs HTML. Who converts one into the other?

Microsoft Web Technologies

Templates

The bad answer: gluing strings together

html = "<h1>" + article.Title + "</h1>"
     + "<p>"  + article.Body  + "</p>"

Unreadable

The shape of the page is buried in quotation marks and plus signs. Nobody can see the document any more.

Unmaintainable

Every change to the markup means editing code, and every missing angle bracket is a bug you find by looking at a broken page.

Unsafe

If a title contains markup, that markup becomes part of the page. This is a genuine security hole — Session 09.

The good answer is older and simpler: a document with holes in it.

Microsoft Web Technologies

Templates

A template plus data becomes HTML

Microsoft Web Technologies

The idea of the session

All of this happens on the server,
before the response is sent.

The browser never sees the template, never sees a placeholder, never runs the loop. It receives finished HTML and nothing else. That is server-side rendering.

How we prove it

Right-click → View page source. That is what arrived. Search it for a placeholder: there is none.

Not the Elements panel

Elements shows the browser's live tree, which scripts may have changed since. For "what did the server send?", view source is the honest answer.

In Session 01 we opened the Response panel and read raw HTML off a public site, and said that this was what our app would spend the rest of the course producing. This is the machinery that produces it.

Block 6 · 30 min

Razor: syntax, @model, control flow

The same idea, with a name and a file extension.

Microsoft Web Technologies

Razor

Every ecosystem has a template engine

EcosystemEngine
.NETRazor — ours
JavaThymeleaf, JSP
PythonJinja, Django templates
PHPBlade, Twig
Node.jsEJS, Handlebars

The syntax differs. The idea is identical.

Every one of them is a document with holes, plus an engine that fills them on the server. Learn the idea once and the next one costs you an afternoon.

Our file extension is .cshtml

C# + HTML in a single file. Mostly HTML, with C# where the holes are.

Microsoft Web Technologies

Razor

How the framework finds a view

ArticlesController.Index()   ->   Views/Articles/Index.cshtml
└───────┬────────┘ └──┬──┘              └───┬───┘  └──┬──┘
   controller      action                controller  action

Drop the word "Controller"

ArticlesController becomes the folder Views/Articles. The action name becomes the file name.

Then Views/Shared/

If the file is not in the controller's own folder, the framework looks in Views/Shared. That fallback is what makes layouts and shared partials work.

Convention, not configuration

Nothing registers a view anywhere. Put the file in the right place with the right name and it is found — Session 03's error message was this rule, read aloud.

We create Views/Articles/Index.cshtml and reload. The error page from Session 03 disappears, and we are looking at our own HTML.
Microsoft Web Technologies

Razor

One symbol to learn: @

@* a Razor comment — never reaches the browser *@

<p>It is @DateTime.Now.ToShortDateString()</p>

<p>2 + 2 = @(2 + 2)</p>   @* brackets when unclear *@

@{
    var greeting = "Hello";
    var count = 3;
}
<p>@greeting — @count articles</p>

<p>name@("@")example.com</p>   @* a literal @ *@
  • @ means "switch from HTML to C# here."
  • Razor works out where the C# ends by itself. You do not close it.
  • @{ … } is a block of statements; @expression prints one value.
  • Inside { } you are in C#. Inside a tag you are in HTML. @ switches back.
  • This feels strange for about a day, and natural afterwards.
Microsoft Web Technologies

Razor

Conditionals: markup inside a decision

@if (Model.Count == 0)
{
    <p class="text-muted">No articles yet.</p>
}
else
{
    <p>@Model.Count article(s)</p>
}

The empty case is not an edge case

A brand-new blog has no articles. A search returns nothing. A filter matches nothing. A page that shows a blank hole in those cases looks broken.

We test it by emptying the list

The only way to know the empty branch works is to run it. We comment out the seed data and reload.

Microsoft Web Technologies

Razor

Loops: the workhorse of every list page

<ul>
@foreach (var a in Model)
{
  <li>
    <a asp-action="Details" asp-route-id="@a.Id">
      @a.Title</a>
    <small>@a.PublishedOn.ToString("d MMM yyyy")</small>
  </li>
}
</ul>
  • One <li> is written; a hundred are produced.
  • HTML and C# alternate with no ceremony and no string concatenation.
  • asp-action and asp-route-id — Session 04's generated links, now in their natural home. No hard-coded href.
  • The browser receives a hundred <li> elements and no loop.
Microsoft Web Technologies

Razor · rule 1

Razor HTML-encodes everything it prints

@* the controller supplies a title of: *@
article.Title = "<b>Breaking</b>";

<h2>@Model.Title</h2>

Razor sends:
<h2>&lt;b&gt;Breaking&lt;/b&gt;</h2>

The reader sees the characters, not bold text:
<b>Breaking</b>

Why this is the default

Article titles, comments and names come from people. If markup in them became part of the page, a visitor could add a script to your site. Encoding makes text stay text.

@Html.Raw(…) removes the protection

It exists, it is occasionally right, and it is a decision. If you ever type it, be certain you know where the string came from. Full treatment in Session 09.

Microsoft Web Technologies

Razor

@model — telling the view what it was given

@model List<SimpleBlog.Models.Article>

<h1>Articles</h1>
@foreach (var a in Model)
{
    <p>@a.Title</p>
}

Two words, one letter apart

@model — lowercase — declares the type, once, on the first line.

Model — uppercase — is the object the controller passed.

The payoff

The editor now knows what Model holds: completion as you type, and a compile error rather than a broken page. We type @a.Titel and watch the squiggle appear.

Without the declaration the view has no idea what it was handed, every property access is guesswork, and typos surface as an exception in front of a user.
Microsoft Web Technologies

Razor · rule 2

The controller supplies; the view displays

// ArticlesController.cs — Session 03, finished
public IActionResult Index() => View(_articles);
                                       └── becomes Model

Views must not fetch data

No database calls, no business rules, no decisions about what to show — only about how to show it. If a view needs something, the controller supplies it.

This is Session 03's traffic rule, enforced one session later.

Why the rule earns its keep

A view that queries data cannot be tested, cannot be reused, and hides slow work inside markup. The bug then looks like a slow page rather than a bad query.

Keep the seam and both halves stay simple.

Microsoft Web Technologies

Razor

Where our stylesheet actually lives

// Program.cs — Session 02
app.UseStaticFiles();

on disk        wwwroot/css/site.css
in the view    <link href="~/css/site.css" />
in the URL     /css/site.css
  • wwwroot is the only folder the server will hand out files from. Everything else — controllers, views, the project file — is invisible to the browser.
  • UseStaticFiles() is the line that turns that on. Remove it and the stylesheet request comes back 404.
  • ~/ means "from the root of the application", so the link keeps working wherever the app is hosted.
The .cshtml files are never served to anyone. They are read on the server, executed, and thrown away — only their output travels.

Block 8 · 20 min

Layouts, partial views and sections

Ten pages need the same header, the same nav and the same footer. We write them once.

Microsoft Web Technologies

Layouts

One frame, reused by every page

Microsoft Web Technologies

Layouts

Views/Shared/_Layout.cshtml

<!DOCTYPE html>
<html lang="en">
<head>
  <title>@ViewData["Title"] — SimpleBlog</title>
  <link rel="stylesheet" href="~/css/site.css" />
</head>
<body>
  <header><nav>
    <a asp-controller="Articles"
       asp-action="Index">Articles</a>
  </nav></header>
  <main>@RenderBody()</main>   @* the view lands here *@
  <footer>@DateTime.Now.Year SimpleBlog</footer>
</body></html>
  • Everything that is the same on every page lives here, and only here.
  • @RenderBody() is the hole. Exactly one per layout.
  • @ViewData["Title"] is a second, smaller hole — each page sets its own tab title.
  • The footer year is computed on every request, so it is never stale.
Microsoft Web Technologies

Layouts

And in the view itself

@model List<SimpleBlog.Models.Article>
@{
    ViewData["Title"] = "Articles";
    Layout = "_Layout";   // usually set once,
                          // in _ViewStart.cshtml
}

<h1>Articles</h1>
<ul> … </ul>

The inversion worth saying out loud

The view does not include the layout. The layout wraps the view.

The same shape as Session 02: we do not call the framework, the framework calls us.

No <html>, no <head>

A view holds only its own content. If you see <!DOCTYPE> in a view, something has gone wrong.

Microsoft Web Technologies

Layouts

Three files whose names begin with an underscore

FileJob
Views/_ViewStart.cshtmlRuns before every view. Sets Layout once, for all of them — which is why you rarely write it in a view.
Views/_ViewImports.cshtmlShared @using declarations and @addTagHelper — this is the file that makes asp-action and <partial> work at all.
Views/Shared/_Layout.cshtmlThe page frame itself.
The leading underscore is a convention, not a rule the compiler enforces. It means: this is not a page, it is a building block. No URL leads to it.
_ViewImports.cshtml answers a question left open in Session 04: asp-controller and asp-action are tag helpers, and this is where they are switched on.
Microsoft Web Technologies

Layouts

Sections: a second hole, for one page only

@* in _Layout.cshtml, at the end of <body> *@
<script src="~/js/site.js"></script>
@await RenderSectionAsync("Scripts", required: false)
@* in Details.cshtml *@
@section Scripts {
    <script src="~/js/articles.js"></script>
}

Why not just put it in the view?

Because a script belongs at the end of the body, and the view's own content lands in the middle. A section lets a page push markup into a different part of the frame.

required: false

Says the section is optional. Leave it out and every view that omits @section Scripts fails at runtime.

A layout can hold several

Scripts, extra stylesheets, a page-specific sidebar. Each is a named hole that a view may fill.

Microsoft Web Technologies

Partial views

A partial view: stop repeating a fragment

@* Views/Shared/_ArticleCard.cshtml *@
@model SimpleBlog.Models.Article

<div class="article-card">
  <h2>
    <a asp-action="Details"
       asp-route-id="@Model.Id">@Model.Title</a>
  </h2>
  <p class="meta">@Model.Author</p>
  <p>@Model.Summary</p>
</div>
@* used from any view *@
@foreach (var a in Model)
{
  <partial name="_ArticleCard" model="a" />
}
The same idea as a method in Session 02 — name a piece of work once, use it in many places — applied to markup instead of code. It has its own @model, and it is given one article at a time.
A layout wraps a page. A partial is dropped into one. A partial is not a small page: it has no layout, no <html> and no URL of its own.

Wrap-up

Common misconceptions (1 of 2)

MisconceptionCorrection
"HTML is a programming language."It is a markup language: structure only, no logic.
"The browser runs the @foreach."The server runs it. The browser receives finished HTML.
"Padding and margin are interchangeable."Padding is inside the border; margin is outside it.
"Elements panel = what the server sent."Elements is the live tree. View source is what arrived.
"@model and Model are the same word."@model declares the type; Model is the object.
Microsoft Web Technologies

Wrap-up

Common misconceptions (2 of 2)

MisconceptionCorrection
"Views can query the database if it's convenient."They must not. Session 03's traffic rule applies here too.
"The view includes the layout."The layout wraps the view, via @RenderBody().
"A partial view is a small page."It is a fragment: no layout, no URL of its own.
"Razor output needs manual escaping."It escapes by default. @Html.Raw removes that protection.
Four of these nine come down to the same sentence: the server does the work, and the browser only ever sees the result.

Lab · 25 min · demonstrated from the front

We give SimpleBlog real pages

  1. We create Views/Articles/Index.cshtml, declare @model List<Article> and return View(_articles).
  2. We list each article — title, author, date — inside an <article>, then empty the list to test "No articles yet."
  3. We add Details.cshtml, linked from the list with asp-action and asp-route-id.
  4. We give _Layout.cshtml a header, nav and footer, and set ViewData["Title"] per page.
  1. We extract the card markup into Views/Shared/_ArticleCard.cshtml and use <partial>.
  2. We add three rules to site.css — element, class, descendant — and confirm each in DevTools.
  3. We title an article <script>alert('hi')</script> and see what appears. Then @Html.Raw, briefly — and revert.
  4. We view source and find the <li> the loop produced.
By the end we will have two views sharing one layout, a list built from a partial with generated links, a handled empty case, and page source containing plain HTML and no Razor syntax anywhere.
