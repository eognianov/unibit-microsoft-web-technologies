The four words

Four words people confuse

WordWhat it isAnalogy
LanguageThe rules for writing instructions a computer can be made to follow.A human language — grammar and vocabulary.
RuntimeThe program that actually executes your instructions on a real machine.The engine. Your code is the driver's input.
SDKSoftware Development Kit: the tools you need to build software — a compiler, project templates, command-line tools. Includes a runtime.A workshop: bench, tools, and a spare engine to test with.
FrameworkA large body of pre-written code that solves the common problems of a kind of application, so you only write the parts unique to yours.A house's foundation, plumbing and wiring. You decorate the rooms.

The four words

What contains what

The kit is what you install. The stack on the right is what exists while a request is being answered.

Microsoft Web Technologies

The four words

Why frameworks exist: what would we build ourselves?

After Session 01 we know what has to happen to serve one page. Here is the list, if nobody helped us.

  • Listen on a network port.
  • Read raw bytes and parse them as a request.
  • Work out which of our code should handle this path.
  • Read files from disk and produce HTML.
  • Format a response and write the bytes back.
  • Handle a thousand people doing this at once, safely.
  • Do all of it without crashing — and log it when it does.
Microsoft Web Technologies

The point of a framework

None of that is your blog.
All of it is the same for every website ever built.

A web framework is that list, already solved, and tested by millions of users before it reached us.

Microsoft Web Technologies

The four words

The inversion: who calls whom

So learning a framework is mostly learning where to put your code and what to name it — a theme for the whole course.

Microsoft Web Technologies

The four words

The cost: a framework has opinions

Follow the conventions

You write very little code

Put the file where it is expected, give it the expected name, and things simply work. Most of what looks like magic is a naming rule you have not met yet.

Fight the conventions

You write a great deal of code

Every deviation has to be configured, explained and maintained. It is possible, and occasionally right, but it is never free.

In this course we follow them. Once the conventions are second nature, breaking one on purpose becomes a reasonable decision rather than an accident.

Now the names

Why C# for the web?

  • Statically typed — the compiler catches whole classes of mistake before the program ever runs.
  • Mature tooling — one command-line tool does everything, on any operating system.
  • First-class database support — Sessions 07 and 08.
  • It is what industry in this region hires for.

Said honestly

The concepts in this course are the same in Java, Python, PHP and JavaScript. You are not learning one company's product — you are learning web development, in one dialect.

C# is not .NET

C# is the language; .NET is the platform that runs it. Other languages run on .NET too.

Many branches on one value: switch

{
    case "draft":
        Console.WriteLine("Not visible"); break;
    case "published":
        Console.WriteLine("Live");        break;
    default:

C# essentials II

Three collections, three questions

string[]

Array

A fixed row of boxes, numbered from 0. The number of boxes never changes.

List<string>

List

A row of boxes that grows and shrinks as you add and remove things.

Dictionary<string,int>

Dictionary

A lookup table: give me the value filed under this key.

Those angle brackets say what kind of thing is inside. List<string> is a list of strings; Dictionary<string,int> files whole numbers under text keys.

C# essentials II

Methods: name a thing once, use it everywhere

string Shorten(string text, int maxLength)
{
    if (text.Length <= maxLength) return text;
    return text.Substring(0, maxLength) + "...";
}

Console.WriteLine(Shorten("A long title", 6));
  • A named, reusable block: inputs (parameters) in, one output (the return value) out.
  • The type in front of the name is the type of what comes back. void means "nothing comes back".
  • Written once means fixed once.

C# essentials II

Classes, objects and properties

class Article
{
    public int Id { get; set; }
    public string Title { get; set; } = "";
    public string Author { get; set; } = "";
    public DateTime PublishedOn { get; set; }

    public bool IsRecent()
        => PublishedOn > DateTime.Now.AddDays(-7);
}
var a = new Article { Id = 1, Title = "Hello" };
  • A class is a blueprint. An object is one thing built from it.
  • A property is a named piece of data on that thing. { get; set; } means readable and writable.
  • Article is the form; each filled-in form is an object.
  • This exact class becomes a database table in Session 08.

C# essentials II

When something goes wrong: try / catch / finally

try
{
    var text = File.ReadAllText("missing.txt");
    Console.WriteLine(text);
}
catch (FileNotFoundException ex)
{
    Console.WriteLine($"No such file: {ex.Message}");
}
finally
{
    Console.WriteLine("This always runs.");
}
  • Some failures cannot be prevented: the file is gone, the network is down, the user typed nonsense.
  • An exception is the language saying "I cannot continue here."
  • finally runs either way — success or failure.
Microsoft Web Technologies

C# essentials II

An uncaught exception has a status code

500

This is where the 500 came from

Unhandled, an exception stops the program. In a web application the framework catches it at the very edge and answers with 500 Internal Server Error — the code we met in Session 01. Whose bug? Ours.

Do not catch what you cannot handle

An empty catch { } hides a bug; it does not fix one. Catch an exception only when you have something sensible to do about it — show a message, use a default, try again.

Querying collections

Four operators that answer almost every question you will ever ask a list.

Microsoft Web Technologies

Querying collections

"Given 500 articles: this year's, newest first, titles only."

// with loops, roughly:
var chosen = new List<Article>();
foreach (var a in articles)
{
    if (a.PublishedOn.Year == 2026)
        chosen.Add(a);
}
chosen.Sort(/* by date, descending */);

var titles = new List<string>();
foreach (var a in chosen)
    titles.Add(a.Title);
  • Twelve lines, three of which are the actual question.
  • Every list we ever filter needs the same twelve lines again.
  • LINQ is the same work, written as the question instead of the procedure.
Microsoft Web Technologies

Querying collections

Where and Select

// which ones match? — same count or fewer
var recent = articles
    .Where(a => a.PublishedOn.Year == 2026);

// what do I want from each one? — same count
var titles = articles
    .Select(a => a.Title);

Read the arrow as "goes to"

a => a.Title: for each article a, go to its Title. It is a tiny method with no name — a lambda.

Filter, then transform

Where changes how many. Select changes what each one is.

Microsoft Web Technologies

Querying collections

OrderBy and FirstOrDefault

// in what order?
var ordered = articles
    .OrderBy(a => a.PublishedOn);

var newest = articles
    .OrderByDescending(a => a.PublishedOn);

// give me one, or null if there is none
var first = articles
    .FirstOrDefault(a => a.Author == "Ada");

First throws

When nothing matches, First raises an exception — and an uncaught one is a 500.

FirstOrDefault returns nothing

It hands back null, which we check. "Not found" is a 404, not a crash — exactly the decision we make in Session 03.

Microsoft Web Technologies

Querying collections

Chained, they read like the sentence we started with

var result = articles
    .Where(a => a.PublishedOn.Year == 2026)   // this year's
    .OrderByDescending(a => a.PublishedOn)     // newest first
    .Select(a => a.Title)                     // titles only
    .ToList();
Twelve lines became five, and the five say what we want rather than how to get it.
These same four operators run against a database in Session 08, unchanged. That is the payoff for learning them now.

Wrap-up

Common misconceptions

MisconceptionCorrection
"C# and .NET are the same thing."C# is the language; .NET is the platform that runs it. Other languages run on .NET too.
"I need Visual Studio, or Windows."The SDK and the dotnet command are the whole toolchain. Any editor, any operating system.
"var means the variable has no type."It has exactly one type; the compiler works it out.
"A compiler error means I broke something badly."It means the compiler caught a mistake before it could hurt. That is the feature.
"A class and an object are the same."Class = blueprint. Object = one thing built from it.
"A list and an array are interchangeable."Arrays are fixed-length; a List<T> grows and shrinks.
"catch fixes the error."It gives you a chance to respond. An empty catch hides bugs.
"LINQ is a database thing."It queries any collection. It also happens to work on databases — Session 08.
"The template's pages are files in wwwroot."They are produced by code and templates. Only CSS, JS and images live in wwwroot.
